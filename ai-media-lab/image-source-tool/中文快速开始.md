# 图片溯源工具：快速开始

这个工具把两件事分开处理：

1. 图里可能是谁、出自哪部作品。
2. 这张具体图片最初发在哪里、是否能找到原画师。

识别出角色，不等于找到了画师。搜索引擎返回的相似度，也不是“作者身份可信概率”。

## 1. 安装

需要 Python 3.10 或以上，以及 Pillow。当前测试环境为 Python 3.12、Pillow 12.3.0。安装命令会从标准 Python 软件源下载依赖；图片不会因此上传。

先解压项目，在包含 pyproject.toml 的 image-source-tool 文件夹里打开终端。

### Windows PowerShell

无需激活虚拟环境，也不用调整 PowerShell 执行策略：

    py -3 -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -e .
    .\.venv\Scripts\python.exe -m image_source_tool "C:\图片\待查.jpg" --output "private-output\第一次检查"

### Linux / macOS

    python3 -m venv .venv
    .venv/bin/python -m pip install -e .
    .venv/bin/python -m image_source_tool "/本地路径/待查.jpg" --output private-output/第一次检查

上面只做本地检查，不访问搜图服务。支持静态 JPG、PNG、WebP；最大20 MiB、4000万像素。动图请先自行选出一帧。

## 2. 明确选择允许上传的平台

下面用 Linux 命令举例。Windows 请把 .venv/bin/python 换成 .\.venv\Scripts\python.exe。

动画截图 → trace.moe：

    .venv/bin/python -m image_source_tool "待查.jpg" --providers trace_moe --allow-upload trace_moe --output private-output/动画截图

角色/作品候选 → AnimeTrace（实验性）：

    .venv/bin/python -m image_source_tool "待查.jpg" --providers animetrace --allow-upload animetrace --output private-output/角色候选

插画原帖候选 → SauceNAO：

    .venv/bin/python -m image_source_tool "待查.jpg" --providers saucenao --allow-upload saucenao --output private-output/插画候选

SauceNAO 需要在当前环境中已有 SAUCENAO_API_KEY。工具不会创建账号、申请密钥、购买额度或保存密钥。不要把真实密钥发到聊天、写进代码或提交到 Git。未配置密钥时会明确显示 missing_credentials。

--providers 指定要查询谁；--allow-upload 单独授权将处理后的图片像素发送给谁。可以显式列出多个平台，但没有“自动上传所有平台”的开关。缺少上传许可时不发送请求。

上传前会在内存里生成新的 PNG，移除 EXIF、GPS、注释等嵌入信息，最长边缩至1600像素以内。画面本身仍会被平台看到，例如水印、人物、聊天内容不会自动遮盖。原图不修改，也不会被自动传到公共图床。

AnimeTrace 的官方示例无需密钥，但本次没有核实正式价格表或固定免费额度；服务可限流或变化。只动态选择启用的默认模型，不启用AI图片判定。trace.moe 有免费额度限制，SauceNAO 按实际账号和返回配额处理。遇到限制会停止，不自动换账号、重试或付费。

## 3. 查看报告

每次会在你指定的目录生成：

- report.html：双击用浏览器打开，查看候选、原生分数、链接与核验清单。
- report.json：供后续脚本读取的结构化证据。

报告不嵌入原图，不自动加载在线缩略图。报告可能包含你的私人搜索线索，分享前仍应检查。重复使用同一输出目录会覆盖其中旧的 report.html / report.json，建议每张图选不同目录。

Linux/macOS 下新输出目录为0700、报告文件为0600；已有输出目录也必须为0700，拒绝符号链接路径。Windows 的权限保护依赖当前用户账户与文件夹 ACL，请使用自己的私人目录，不要使用共享目录。

### 状态怎么看

- matches：有候选，还没证实。
- no_match：平台正常返回，但没有候选。
- not_requested：本次没查询。
- consent_required：尚未授权上传。
- missing_credentials：缺少已有密钥。
- blocked / rate_limited：访问受阻或额度/频率受限。
- network_error / service_error / invalid_response：网络、服务或返回格式问题；不等于搜不到。

终端退出码：0表示所选查询正常完成（包括无匹配）；1表示至少一个平台未能完成；2表示本地输入或输出失败。即使某个平台失败，也可查看其他平台的结果。

报告中的角色、作品、原图来源、原画师结论默认保持 unresolved。请核对候选原帖的画面、账号归属及署名，再决定能否归因。转载站、高分、最早被搜索引擎收录或更高分辨率，都不能单独证明原创。

## 4. 哪些已经做了，哪些还需要人工

- 已实现：本地检查、隐私处理、三种API适配器、静态报告、分平台上传许可及失败状态。
- 已验证：27项合成图/模拟响应单元测试、离线运行、软件包构建，以及报告JSON结构校验。这些测试不会联网搜图。
- 在线结果：必须以实际运行的平台状态和原帖证据为准。模拟测试通过，不代表当前网络能连通、服务始终在线或一定能找到来源。
- IQDB、ascii2d、Google Lens、TinEye：仅提供人工入口，没有在后台自动搜索，也没有把打开首页当成查询成功。
- 没有部署完整本地动漫角色模型，没有抓取全网图库，也没有恢复已退役的 Bing Search API。

运行离线测试：

    .venv/bin/python -m unittest discover -s tests -v

Windows：

    .\.venv\Scripts\python.exe -m unittest discover -s tests -v

GitHub工具与官方接口的比较见 research/provider-review-2026-10-05.md；英文技术说明见 README.md。
