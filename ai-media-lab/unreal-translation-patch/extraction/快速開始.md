# 先把虛幻文本正確提取出來

目前已完成：從 **5 個真實 `.locres` 二進位資源提取 17 筆文字**，逐筆對照作者的 `.archive`／CSV，命名空間、鍵、來源雜湊、文字及重複次數全部吻合。提取和翻譯是獨立子資料夾，這一步不需要翻譯 API 或 API 金鑰。

## 選用什麼驗證？

自行選擇兩個作者公開、採 MIT 授權的 Unreal 範例專案：

- Lucas Guichard／TechNet 的 VideoExample（UE5.3）：英文 7 筆、法文 7 筆。
- Damian Nowakowski 的 EasyLocalizationToolExample（UE4.27）：英文、德文、波蘭文各 1 筆。

它們是含真實遊戲 UI 本地化資源的範例專案，不是已安裝並啟動驗證的完整商業遊戲。驗證確實讀取作者原始二進位檔，並非把自造文字當成遊戲結果；但目前只證明「獨立 `.locres` → 文本」這一段。

## Windows PowerShell 快速開始

先安裝 Python 3.9 或更新版本。在專案根目錄開啟 PowerShell：

```powershell
cd .\extraction
python .\fetch_samples.py
python -m unittest -v
python .\verify_samples.py
```

如果你的電腦以 `py` 啟動 Python，將上述 `python` 改成 `py -3`。

預期結果：13 個測試通過，報告中的 `total_resources` 是 5、`total_entries` 是 17，每個資源的 `exact_match` 都是 `true`。下载僅包含已釘選提交及 SHA-256 的小型資源、參考文字、專案描述和授權文件，不包含遊戲執行檔。網路不可用時會報錯，不會偽造成功。

單獨提取法文資源：

```powershell
python .\locres.py .\fixtures\video-example\Content\Localization\Game\fr-FR\Game.locres --json .\results\my-export.json --csv .\results\my-export.csv
```

預期顯示 `Extracted 7 entries (locres version 3).`。JSON／CSV 是 UTF-8。若目標已存在，工具會停止，請改用新檔名；只有確定要覆寫自己的輸出時才加 `--force`。它拒絕覆寫輸入資源，也拒絕把 JSON／CSV 指向同一檔案。

## 你會拿到什麼？

- `results/verification.json`：每份真實資源的筆數、SHA-256、逐筆比對結果。
- `results/video-example-en.json` 等檔案：完整提取記錄。
- 對應的 CSV：方便查看或交給後續翻譯流程。若拿未知來源 CSV 用試算表開啟，留意公式字串的安全風險。

每筆保留 `namespace`、`key`、`source_hash`、`text` 等欄位，不會因文字相同就刪掉記錄。`text` 是所選語言資源內的文字，未必是原文。

實際例子，均來自 VideoExample 專案 `Content/Localization/Game/`，並由同語言 `.archive` 獨立核對：

- 英文 `en/Game.locres`：`Play`。
- 法文 `fr-FR/Game.locres`：同一鍵對應 `Jouer`。
- 法文 `ST_CommonWords` 命名空間、`Credits` 鍵：`Crédits`。

## 目前沒有保證的部分

- 尚未驗證 PAK／IoStore 解包，也不處理加密資源或繞過限制。
- 尚未驗證啟動遊戲、執行時抓取畫面文字或文字替換。
- 尚未直接解析 `.uasset` 的 StringTable；範例中的 StringTable 文字是從已編譯 `.locres` 讀到的。
- 不代表「全遊戲所有文字」均可提取；硬編碼、圖片、伺服器或未收集進本地化資源的文字可能不在其中。
- 兩個真實專案的資源版本都是 locres v3。v0／v1／v2，以及中文、emoji、佔位符等邊界案例另有合成測試，不冒充真實遊戲覆蓋率。

來源、不可變提交、SHA-256 及授權資訊見 `samples.json`、各下載範例中的 `LICENSE` 和 [README](README.md)。
