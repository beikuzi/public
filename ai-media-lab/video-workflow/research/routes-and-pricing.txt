Video-analysis route research — verified 2026-10-04, documentation research only

Recommendation
Start with existing captions plus timestamped frames. If captions are missing or unreliable, compare local faster-whisper CPU small/int8 against base/tiny, reusing identical extracted audio/frames. Paid APIs remain priced alternatives until upload/payment authorization and access exist. ASR does not see visuals; a caption-only summary cannot establish scene facts, actions, colors or on-screen text.

1. Existing-caption route / Bilibili
The current yt-dlp Bilibili extractor reads subtitle metadata per video/cid and converts from/to/content JSON into SRT. It can report that subtitles require login. Danmaku is exposed as an XML subtitle track but is audience commentary, not speech captions. Keep separate provenance. The current comments extractor pages a fixed sorting mode, stops when no replies are returned, and recurses only into replies included by the endpoint. This does not prove exhaustive nested-comment coverage. Save video ID, cid/part, language, human/AI status, duration, fetched time, page/sort, root/comment IDs, and sample counts. Do not call comments representative audience sentiment; popularity sorting, moderation, deletion, non-commenting viewers and retrieval failure bias the sample. Empty result can mean inaccessible, not absent. No cookie export, login barrier bypass, geo/paywall bypass, fingerprint workarounds or unlimited retries.
https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py

A still-open issue describes Bilibili AI subtitles appearing with normal subtitle tracks (ai-zh, ai-en). Explicitly inspect labels instead of assuming --write-subs means human captions.
https://github.com/yt-dlp/yt-dlp/issues/14463
Publicly viewable does not mean openly licensed for downloading/republication; prefer creator-provided downloads, user-owned media or an explicit compatible license. Platform terms:
https://www.bilibili.com/blackboard/protocal/licence.html

2. Local route
faster-whisper official benchmark: 13 min audio, small/int8 CPU, beam 5, 8 threads on i7-12700K: 1m42s and 1477MB RAM; batched 8: 51s and 3608MB. This is vendor benchmark, not our environment. Pin package/model revision; consume segment generator fully before timing. Measure VAD on/off because clipping short speech is a quality risk. Use multilingual small, not small.en. Whisper supports zh; dialect and technical terminology still require a representative evaluation.
https://github.com/SYSTRAN/faster-whisper
https://github.com/openai/whisper/blob/main/whisper/tokenizer.py
whisper.cpp is an alternative C/C++ CPU implementation with quantization, useful when Python dependencies or memory are inconvenient; benchmark rather than assume faster.
https://github.com/ggml-org/whisper.cpp
FFmpeg frame sampling plus scene selection: retain a periodic safety sample even when no scene change is detected. Start one frame/5sec for lecture-like videos, scene boundary frames and OCR crops; increase around actions or small text. Retain actual PTS/time base, not frame number as seconds. Frame sampling misses brief events. PaddleOCR supports Chinese and can run separately on captions/slides; OCR is neither full visual understanding nor an independent speech reference when burned-in subtitles were generated by ASR.
https://ffmpeg.org/ffmpeg-filters.html
https://github.com/PaddlePaddle/PaddleOCR

Comparison protocol (proposal, not measured results)
Freeze same legal video bytes/hash, selected language/audio track and exact test interval. Preserve original and normalized transcript. Chinese primary metric CER=(substitutions+deletions+insertions)/reference characters; normalize punctuation/space and simplified/traditional consistently and disclose normalization. English WER on same spoken words. Reference must be manually checked against audio, not a competing ASR output or translated/abridged captions. Report proper-name/number errors separately. Do not score before reference coverage is established.
Create visual QA independently from audio: e.g. 10 observable questions with timestamp/frame evidence and explicit unsupported/unclear response; mark correct/incorrect/unanswerable and missed short events. Keep audio facts and visual facts separate. Comments assessed for provenance/coverage, not truth.
Measure source acquisition, decode, model download, load, inference, OCR, summary and total separately. Cold first use versus warm loaded model; three warm repetitions if affordable, median/range, hardware/thread/model/settings. RTF=processing seconds/media seconds. Include observed billed tokens/seconds, retries, data transfer and compute rental; local API fee zero is not necessarily total cost zero. Cache by media hash+model revision+settings+prompt; save JSON segments, SRT/VTT/TXT, frame timestamp manifest, OCR JSON and QA evidence. Reuse derived artifacts and rerun only uncertain spans.
https://jitsi.github.io/jiwer/usage/
